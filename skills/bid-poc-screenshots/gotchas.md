# bid-poc-screenshots - Gotchas

这些是从实践中学到的反直觉知识和常见陷阱。

## Gotchas

### 截图失败必须如实标 FAILED，绝不假装成功

**问题**：浏览器运行时不可用时，截图一张没生成，但本 skill 历史上仍标 SUCCESS，把"截图待手动生成"塞进脚注，导致用户拿到一份缺关键证据、看似完成的标书。根因之一是 host 侧 extension 把异常吞成 ❌ 文本而非 throw，框架误判"工具完成"。

**解决**：调用 `poc_screenshot` 后，**核对返回的截图数量**。若截图为 0 张或工具报错，完成状态块必须标 `FAILED` 并写明原因（如"浏览器运行时不可用，0 张截图"），供 bid-manager 把本阶段标红、不进 ✅。**禁止**用"待手动生成"掩盖失败。

---

### 调用截图工具前先探活浏览器运行时

**问题**：未探活就调用，Puppeteer 在沙箱外启动失败，白白等待超时。

**解决**：前置检查除确认 POC 目录/占位符存在外，加一步 `curl /api/v1/health/preflight` 查 puppeteer 字段，或直接试启一次浏览器。不可用时直接 `状态: SKIPPED, 原因: 浏览器运行时不可用`，不徒劳调用。

---

### 占位符编号与 POC 子目录编号必须同源

**问题**：占位符里提取的 `S\d{2}` 与 POC 子目录前缀对不上，匹配失败，截图插不进。

**解决**：两者都应源自 `system_decomposition.json`（tech-proposal 占位符从 json 复制、POC 子目录从 _metadata.md 镜像命名）。匹配不上时，先核对编号体系是否一致，而非保留占位符了事。
